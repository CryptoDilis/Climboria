## Reconciliation contract for a future read-only indexer
- Anchor chain ID, exact candidate manifest, Safe, guard, token, destination addresses and code hashes. Never trust arbitrary log emitters or derive authorization from event names alone.
- Obtain canonical finalized transaction/receipt with matching block hash and successful receipt status. Decode the actual Safe transaction target, operation, data and nonce; require the typed guard call and successful Safe execution, not a mere successful outer transaction. Validate exact expected selector and calldata length, historical guard configuration and bound vault; do not assume latest state describes historical authorization. Verify Safe transaction hash and quorum against historical owner configuration (including signature mode restrictions). If historical proof is unavailable, remain unverified.
- Expense: decode expected epoch, vault index 3..5, recipient, amount, evidence, month, nonce and signed validity bounds. Compute Ethereum Keccak-256 of Solidity abi.encode(chainId, vault, token, purpose, epoch, recipient, amount, evidence, month, nonce). Match exactly one Proposed(bytes32,uint256,bytes32,address,uint256,uint256) from that vault: indexed ID/epoch/evidence, data recipient/amount/readyAt. The event omits month and nonce; calldata is necessary. Compare readyAt to inclusion timestamp + DELAY. Confirm persisted proposal at appropriate historical state; never interpret Proposed as payment.
- Liquidity: decode expected epoch, asset and quote amounts, minShares, deadline, nonce and signed validity bounds. Compute Ethereum Keccak-256 of Solidity abi.encode(chainId, vault, asset, quote, pool, epoch, assetAmount, quoteAmount, minShares, deadline, nonce). Match exactly one Scheduled(bytes32,uint256,uint256,uint256,uint256,uint256) from bound liquidity vault: indexed ID/epoch; data assetAmount/quoteAmount/readyAt/deadline. The event omits minShares and nonce. Confirm action storage, no execution implied.
- Retain block hash, tx hash, log index, Safe tx hash, calldata hash, canonical ID, emitter, epoch, evidence where applicable, and verification result. A reorg invalidates orphaned records and dependent execution records. Duplicate observations must be idempotent. Reject missing, duplicate, inconsistent, unfinalized or wrong-emitter records. Do not send a transaction, sign, or release funds based on indexer output.
- Track cancellation and execution as independent finalized lifecycle transitions, including registry consumption and exact token transfer or LP-lock evidence. A proposal's current eligibility must be queried at execution; a historical approval is not proof of current spendability. Production pool economic backing, independent RPC/finality, event indexing, and beneficial ownership screening remain open.
