## Recommended smallest production direction (not approved)
Default: zero-funded liquidity deferral; select one real adapter architecture before any production issuance that promises future liquidity. Prefer V2-style fungible LP for the simpler fixed-lock model if an actual supported Base deployment can be independently verified and the owner selects it. Do not automatically choose protocol, stablecoin/WETH, fee, price or liquidity amount. An indefinitely locked reserve with no credible activation route is not equivalent to deferred liquidity.

Design boundary: reserve must hold only the existing 25% allocation; pre-commit exact adapter code and chain, quote identity, custody and permitted activation interface. No arbitrary adapter substitution, unlimited approval, generic calls, rescue of CLIMB, operator-chosen recipient or hidden founder bypass. A one-time binding mechanism would require separate reviewed authority and exact immutable constraints; no contract implementation authorized by this proposal. No pool creation by arbitrary builder during issuance. If preselected adapter cannot be safely bound before issue, defer issuance. Liquidity activation is a separate quorum action, even if issuance is approved.

## Acceptance gates before implementing or funding
1. Owner selects deferral or an exact protocol, quote asset and funding ceiling; explicit initial float, price/range, per-tranche limits, lock/custody and fee/exit rules. No manufactured volume, price guarantee or assumption that reserve equals market liquidity.
2. Independently verify chain-specific factory/router/manager, actual runtime, proxy/admin if applicable, token behavior and factory pair/pool identity at authenticated block; review exact upstream deployment source, licensing and hashes. No guessed addresses or unreviewed source.
3. Bind action to current epoch, unique nonce, exact pair, max amounts and min actual amounts, deadline, approved recipient and price bounds. Validate pool initialization or existing state; protect against stale quotes, malicious pre-initialization, donation/ratio manipulation and misleading return values. Measure actual deltas; record actual consumed CLIMB, not desired maximum. Keep leftovers in original restricted vault; zero residual allowance. Revert atomically on mismatch. No unchecked external callbacks or arbitrary calldata.
4. For V2 require actual LP minted directly into approved fixed locker, measured share increase, backing and no unauthorized early removal. For V3 require exact NFT tokenId/owner, positions pair/fee/ticks/liquidity, no approvals or permits, no decrease/collect/transfer path that bypasses lock; specify third-party added liquidity, donations and fee/principal policy. Post-lock assets remain controlled by reviewed restricted custody, not unilateral founder wallet.
5. Test malicious factory/router/manager, wrong pool, wrong token, existing manipulated state, slippage, partial consumption, callback/reentry, expiry, stale epoch, replay, canceled action, failed transaction rollback, lock bypass and post-lock custody using pinned real protocol code in local environment. Then separately authorized testnet proof. Recompute entire release build, exact runtime/ABI/layout and size checks, targeted AI security re-review. No production deployment until all applicable gates.
6. No initial liquidity activation without actual quote funding and risk disclosures; game rewards and legacy compensation have independent gates. No approval to change other workstreams.
