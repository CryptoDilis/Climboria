# Isolated wallet-only governance forum backend
Status: source implementation, not deployed. Default FORUM_ENABLED=false; placeholder D1 ID is local-only. No route or deploy workflow. No existing auth, game, DEX, Swap or token contracts changed. Supported authentication: Ethereum ECDSA key ownership via server-generated EIP-4361-format challenge scoped to Base (8453) and climboria.fun. Chain selection is a signed statement, not proof of wallet network state; client must check chain before signing. EIP-1271 contract-wallet signatures are not supported in this first implementation. No email/session fallback. Opaque one-hour bearer tokens hashed in D1; client must keep tokens in memory, never localStorage or URL, clear on wallet account/network change and logout. No token approvals or transactions. CORS exact origin and POST origin checks; bearer is still a secret, origin alone is not authentication. No production IP or nonce logs. Cloudflare edge IP rate limiting plus D1 per-wallet rate limits; rate limits alone cannot prevent Sybil spam. Schedule cleanup after provisioning; no scheduled trigger in default config.

Implemented endpoints: GET /v1/health, POST challenge/verify/logout, public GET topics and paginated replies, authenticated POST topics/replies/reports. Plain text only; clients must render using textContent, never HTML. Reports private, no moderator action implemented; formal proposal/vote, reactions, edits/deletes and moderation disabled. Topics tagged governance are ordinary discussion, not formal voting. All DB writes go through this isolated Worker; never expose D1 credentials publicly. No production claims.

Next: exact-head CI with real local D1, review dependency lock and security findings, implement separate UI client with Base wallet proof, account/network-change handling, real browser + two-wallet integration, moderation role provisioning and controls, abuse limits, audit/log retention and cleanup schedule. Provision private forum-only D1 and separately scoped Worker route only after review, apply migrations, configure staging/production exact origin and test real wallet accounts before enabling. Formal proposals/votes require reviewed CLIMB staking/checkpoints; no fake votes. Treasury monitoring remains blocked by production CA and registry.
