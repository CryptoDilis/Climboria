# Base Sepolia test-only token

This scaffold is **NOT official Base CLIMB**, not audited production code, not deployed, and not a bridge. Constructor rejects every chain ID other than 84532. Name and symbol intentionally differ from real CLIMB. Six decimals, zero initial supply, cap 1,000 test tokens. Only a once-bound code-bearing manager can mint or burn its own balance; the binder cannot mint. There is no upgrade or manager replacement path. A malicious or misconfigured manager can still mint up to the test cap: binding is not proof of backing.

References: [NTT EVM v2 interface](https://github.com/wormhole-foundation/native-token-transfers/blob/c636cc15b07969e4b44de7e466c999c07e7387a9/evm/src/interfaces/INttToken.sol) and [upstream dummy](https://github.com/wormhole-foundation/native-token-transfers/blob/c636cc15b07969e4b44de7e466c999c07e7387a9/evm/src/mocks/DummyToken.sol). The upstream dummy publicly mints and is inappropriate for this setup. NTT requires mint and burn; setMinter is optional. This implementation intentionally uses one-time binding. [OpenZeppelin 4.9.6 exact source](https://github.com/OpenZeppelin/openzeppelin-contracts/tree/dc44c9f1a4c3b10af99492eed84f83ed244203f6).

CI only compiles and tests with a mock manager and local chain-ID changes. It does not deploy or broadcast, connect to a wallet, prove NTT integration, or estimate deployment cost. No secrets. Testnet deployment requires a distinct Solana test mint, exact reviewed NTT manager code, peer settings and explicit testnet authorization. Do not copy this scaffold into mainnet or announce any address.
