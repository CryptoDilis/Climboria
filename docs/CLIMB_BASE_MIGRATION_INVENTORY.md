## Offline reconciliation
The new migration-inventory.mjs accepts two normalized snapshots with fields mint, program, decimals, commitment (finalized), slot (safe positive integer), genesis, blockhash, complete (true), supplyRaw (decimal integer string), and accounts (array). Each row contains address, owner (token authority, not RPC program owner), mint, program, state (initialized/frozen), amountRaw (decimal integer string). Call reconcileInventories(a,b,{expectedGenesis}) using a separately sourced mainnet genesis reference. All addresses and hashes must decode to 32 bytes. Collect and independently validate raw source evidence before normalization. Matching total supply alone is insufficient; compare every positive token account and owner at the same finalized slot/block. Zero accounts do not affect positive holdings. Duplicate account rows, conflicting owner/amount/state, invalid values and different slots fail closed. Outputs are aggregate counts and digest, not holder list or allocation. A matched result is arithmetic only, not source authenticity, completeness proof, beneficial ownership, eligibility or deployment permission. Synthetic fixture tests only; CI pending.
