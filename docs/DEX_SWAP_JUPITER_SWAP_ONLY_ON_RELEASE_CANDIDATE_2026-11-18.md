## Follow-up: user Close / approved reopen widget visibility guard
Official Jupiter [`src/library.tsx`](https://github.com/jup-ag/plugin/blob/main/src/library.tsx) shows `Jupiter.close()` sets the vendor's own widget container `display:none`; `Jupiter.resume()` restores `display:block`. The prior Climboria user Close button only hid its enclosing first-party panel, which could leave third-party-owned elements visible. The pending release branch now calls provider `close()` best effort after the user closes a mounted widget; a subsequent explicitly clicked, fresh-no-store-approved reopen calls `resume()` **only** if the vendor container was successfully hidden through this path. A missing/throwing `resume()` fails closed with a refresh explanation rather than claiming the wallet interface reopened. On rollback, the existing hard-deny path still blocks `resume()`. This cannot dismiss a separate wallet popup, reverse an already-signed transaction, or prevent all browser/vendor bugs.

Regression evidence added in `.github/scripts/dex-swap-managed-provider-shell.test.mjs`: manual close/reopen call counts, missing/throwing `resume()`, revoked approval before reopen and throwing vendor close. Synthetic Playwright `.github/scripts/dex-swap-managed-provider-browser-smoke.mjs` now models the third-party root's display change, requiring it to be hidden on Close and restored on approved reopen without repeated `Jupiter.init()`. All of this is **mocked SDK acceptance only**, pending fresh PR-head CI and later real vendor/device testing. No public ON switch changed by this guard.

## Follow-up: pending Jupiter initialization close/revoke race

The official Jupiter `init()` is asynchronous and can build a vendor-owned widget before its returned promise resolves. In the earlier host, manual Close and a 15-second operator-status revocation called `Jupiter.close()` only when `mounted=true`. During an in-flight `init()`, `mounted` was still false: the first-party panel was hidden, but there was no *immediate* best-effort concealment of a partially created vendor-owned overlay. Completion after Close was already guarded by request IDs and late `close()`, but that did not cover the in-flight interval or an SDK `init()` rejection after partial UI creation.

The draft release branch now tracks `providerInitInFlight`, invokes best-effort provider `close()` **immediately** on manual Close or revocation during initialization, **again** if a stale async `init()` later resolves, and calls `close()` when `init()` throws or rejects after partial construction. Following failed init it conceals the first-party panel, stops active status polling, hides its launcher and requires a full refresh before retrying. The wording expressly says that closing does not cancel third-party wallet requests or submitted transactions. This is defense-in-depth, not a guaranteed cancellation of wallet UI/actions already initiated by Jupiter.

The offline unit regressions in `.github/scripts/dex-swap-managed-provider-shell.test.mjs` cover immediate + late Close calls, operator revocation while init is pending, both synchronously throwing and asynchronously rejecting `init()`, first-party concealment, hidden retry control and stopped polling. All tests require the **new exact PR head**; older green CI does not prove these changes. No production activation or funded trade was performed.

## Follow-up: tab-return vendor-owned overlay concealment

**Found during pre-release host review:** On a background tab becoming visible, focus, or BFCache `pageshow`, the previous Climboria UI hid only its first-party provider panel while awaiting an uncached runtime-status response. The Jupiter Plugin independently controls its own widget root via `close()`/`resume()`; therefore a provider-owned overlay could remain visible during the network wait or while the operator had already revoked the release. Hiding the parent panel alone was not a guarantee of concealment.

**Branch-only fix:** `dex/provider-managed-swap.mjs` now synchronously invokes the official Jupiter `close()` to conceal its own root **before** requesting fresh no-store runtime approval on tab return, sets the remembered concealment state, and invokes `resume()` **only after** current approval succeeds and the request ID is still current. A revoked status leaves the root hidden and launch controls inaccessible. If the vendor `close()` or `resume()` is missing/throws, the host fails closed, hides its controls, and requests a refresh rather than treating the UI as safe. This UI protection does **not** cancel an external wallet popup, signed transaction or on-chain settlement.

**Offline regression coverage:** `.github/scripts/dex-swap-managed-provider-shell.test.mjs` now checks immediate vendor concealment before approval response, approved Focus/BFCache root restoration, stale network response fences and missing/throwing `close()`/`resume()`. Synthetic Playwright `.github/scripts/dex-swap-managed-provider-browser-smoke.mjs` now asserts the distinct vendor root is `display:none` *synchronously* after focus/visibility event, only resumes after fresh approval and stays concealed after rollback without duplicate initialization. This is not a real Jupiter wallet test. **Fresh exact-head CI is required**; older 8/8 results do not establish this latest change.

No production approval, source gate, provider fees, native execution or DEX surface changed. Keep [draft PR #618](https://github.com/CryptoDilis/Climboria/pull/618) unmerged until separate official vendor runtime/terms and wallet acceptance review plus explicit operator release authorization.
