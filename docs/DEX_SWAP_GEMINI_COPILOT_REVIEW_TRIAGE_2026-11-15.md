## Static inspection vs tests and evidence

- Both external reports were **source reviews**, not independent dynamic penetrations, live RPC tests, verified program bytecode audits or real-money settlement.
- Prior production-safe Worker tests, release gate checks and quote-only smoke on deployed SHA `ed9dda3` succeeded; see linked workflow runs above. Those successes **do not reproduce Gemini's dormant future-gate exploits**, or verify mainnet source-to-deployed-program parity.
- This triage document itself makes **zero executable-code changes**. No new CI tests were run by this document write.
- Gemini report exact claims about `index.mjs:149-153` as `handleOrder` and `:374-413` as `handleExecute` are incorrect for the actual frozen file: those lines are around the rate limiter / other handlers; verified actual handlers start `handleOrder:171` and `handleExecute:467` frozen (current execute starts line 478 after quote patch). Future reviewers must use actual original file line numbers rather than report-provided guesses.
- Do not accept speculative recommendation to bind order tokens to **IP fingerprints** as sufficient security; proxies/mobile IP shifts and privacy implications make cryptographic wallet signature/session plus short-lived unguessable token and server-side atomic claim more reliable.
